# 背景

- チーム開発をしているが、PRのレビューコストが高くて困っている
- LLMの発展によって実行コストが極端に低くなり、PRが大量に生成されるようになっている
- しかしながら人間によるレビューが必要でありチームMGRである私がレビューをしなければならないことが多い
- LLMによって一気に実装ができてしまうため、PRのサイズも大きくなりやすく、また事前の相談なども少なく、PRを初見で理解をして妥当性を判断するのが非常にきつい...

# 実現したいこと

- レビューコストを下げたい
- 認知負荷が低い状態で、方針を理解することができるようにしたい
- 方針や重要な判断を抽出して、必要な部分について強度高くレビューでき、重要度が低い領域においては強度低く低コストでレビューできるようにしたい

# 基本方針

- LLMを使って実装する際にしている指示や、確認、設計や方針、判断について、即時に他メンバーと共有でき、FBを受けることを受けることができる
- 常に自分のローカルのファイルを操作するような体験で、他メンバーの成果物の確認やLLMを使った修正や指示をすることができる
- 最終的な実装物ではなく、実装の過程からこまめに進捗を共有確認しながら合意形成をして進めることができる
- 気づいたことやFBがあれば、簡単に指摘でき、LLMを使って指示や改善を実行できる

# 方法案

- どのような判断をして、どのような設計を選択してたか...について残した上で、判断や選択された方針が妥当であるかを確認できるようにする
- 粒度の大きい全体の方針から確認し、段階的に詳細の判断や方針について段階的に確認できるようにする
- レビュー依頼などを都度実施することなくに、シームレスに判断や方針を確認・FBしたり、合意しながら進めることができる
- 作業者は特定の個人に特定することなく、最新の進捗状況や設計や判断の状況を共有でき、自由に編集や修正ができLLMに指示をしてタスクを進めることができる
- 他の人が進めている作業に対して、最新の状況や判断の状況を確認して、レビューして必要に応じて編集や修正を指示することができる
- 設計ドキュメントや作成した資料、実装に対してレビューができ承認した結果をマークすることができる
- 承認したのちに他メンバーによって、変更や修正がされている場合更新されていることがわかり、再度確認する必要があることがわかる
- チームで進めているタスクの一覧をCmuxのサイドバーのように一覧で簡単に確認できる
- 各タスクの進捗やステータスも一覧で簡単に確認できる
- 各タスクに対して、AIが対応中なのか、自身がレビュー済みなのか、他メンバーの指示でAIが対応中なのか、他メンバーがレビュー済みなのか...などがわかる

- (できれば) 高速で同期でき、最高の体験性を享受できるようにしたい
