# 解決案カタログ — 検証前の事前登録(2026-08-01)

位置づけ: Run 2a 実施前の、検証結果にバイアスされていない状態での解決案の洗い出し。
方法: 独立3視点の並行起草を統合 — **[G]** 内在ギャップ分析(goal.md の北極星・介在点マップと
リポジトリ内文書の突き合わせ)/ **[E]** 外部知見(コンテキストエンジニアリング・I-PASS/SBAR・
SRE 引き継ぎ・AI レビュー実践・実験計画)/ **[A]** 敵対検証(仮説を殺す経路・作らない解・測定設計の欠陥)。
各視点は互いの出力を見ずに起草した。★ = 2視点以上が独立に収束(信頼度が高い)。

使い方(事前登録の規律): 検証後の投資判断は**このカタログから選ぶ**。カタログに無い案を
検証後に思いついた場合は「事後案」と明示して区別する。全案に goal.md §2 の介在点番号を付す。
発動条件は「無条件(Run 2a 前)」「シグナル待ち(条件を明記)」「Run 2a 後」の3分類。

器の原則 [E・SBAR 定着失敗の教訓]: ゲートは既存の1個(「記録シート未記入ならレビュー依頼しない」)
のまま増やさない。新設する器は3つに限る — **① プロセス規約1枚 ② 記録シート v2 ③ Run 2a 手順書**。
以下の「規」「検」の各案は必ずこの3つのどれかに載せ、独立したチェックリストを作らない。

## 0. 最初に確定すること — 仮説レジストリの更新 ★[A][G][E]

K1 の所見「人間が brief を直接読むのは非現実的」は、**原仮説 H1「brief 1枚で人間が引き継げる」への
棄却データ**であると同時に、**H2「brief は AI が消費し、人間は AI の統合・説明を介して合流する」の
仮の肯定データ**である。このすり替えを暗黙にせず正式に記録し、「Run 2a が測るのは H2」と宣言する。

ただし H2 には交絡が既知: K1 の合流成功は brief とリポジトリ裏取りの寄与が分離できていない
(brief が空でも AI+リポジトリで合流できる可能性を排除できない)。→ 対照(検4)が H2 確証の必要条件。

外部知見による支持: brief 4要素は Anthropic compaction 保存カテゴリ・I-PASS・SRE handover と同型
(骨格は妥当)。K1 で露呈した欠落は I-PASS の中核2機能 anticipation(先回り)/ check-back(読み戻し)の
不在と正確に対応(規3・検2 が処方)。
